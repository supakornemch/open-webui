Network guardrail
OWUI and LiteLLM are VNet-integrated. AI Search and PostgreSQL have public access disabled; private endpoints are required.
SSO dependency
VNet blocks general outbound internet. Entra OAuth requires an NSG outbound allow rule for login.microsoftonline.com.
Index design
OWUI knowledge, file and memory collections are consolidated into three shared Azure AI Search indexes via collection_key.

Request path

  • User -> public ingress -> Open WebUI
  • Open WebUI -> LiteLLM -> Azure AI Foundry
  • Open WebUI retrieves grounded context from Azure AI Search before response generation.

RAG path

  • Documents -> extraction -> classification/chunking -> embedding
  • Chunks stored in enterprise-docs-idx
  • Search uses hybrid vector plus BM25; semantic ranking is optional.

Operational constraints

  • Azure App Service runs Linux/AMD64 container images.
  • One isolated database/environment file per OWUI and LiteLLM service.
  • Runtime internet dependencies must be baked into container images.
